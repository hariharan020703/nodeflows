# Connector Specification: SAP MM (Materials Management)

> Adapted from the canonical spec at `Shared-Library/Connectors/SAP-MM.md`. Any change to authentication, authorization, or core data objects must be reconciled with the canonical version before being adopted here.

## Overview
SAP MM governs spare parts master data, stock levels, purchase requisitions/orders, and vendor master records. This connector allows AI agents to read inventory positions and material master data, and to write back purchase requisitions when spare parts intelligence recommends procurement action.

## Reusability Scope
Canonical connector reusable across Maintenance (Spare Parts Intelligence Assistant), Procurement, and Production Planning departments wherever material stock, BOM, or purchasing data is required.

## Authentication & Security
- **Protocol:** SAP OData services (`API_MATERIAL_STOCK`, `API_PURCHASEREQ_PROCESS_SRV`, `API_BUSINESS_PARTNER`) or SAP BAPI (`BAPI_MATERIAL_STOCK_REQ_LIST`) via RFC middleware for ECC landscapes.
- **Auth method:** OAuth 2.0 client credentials via SAP Cloud Identity Services; on-prem fallback via secure RFC service user.
- **Authorization:** Service user `SVC_AI_SPAREPARTS` scoped to read-only on MM01/MM03 material master and stock views, with restricted write scope limited to purchase requisition creation (ME51N equivalent) — never direct PO release, which remains a human approval step.

## Core Data Objects
| Object | SAP Transaction Equivalent | Key Fields |
|---|---|---|
| Material Master | MM03 | Material No., Description, Material Group, Base Unit, Criticality Class |
| Stock Overview | MMBE | Plant, Storage Location, Unrestricted Stock, Safety Stock, Reorder Point |
| Purchase Requisition | ME51N | PR No., Material, Quantity, Required Date, Requester |
| Purchase Order | ME23N | PO No., Vendor, Net Price, Delivery Date, Status |
| Vendor Master | XK03 | Vendor No., Lead Time, Rating, Preferred Status |

## Integration Pattern
- **Read:** OData GET for real-time stock checks; nightly batch sync of full material master and consumption history to staging SQL for ML-based demand forecasting.
- **Write:** Purchase requisition creation via OData POST, routed through SAP workflow approval (WS20000075 or custom) before becoming a PO.

## Latency & Refresh
- Stock level reads: < 3 seconds. Requisition creation: synchronous, confirmed within 5 seconds, subject to SAP release strategy.

## Error Handling
- Duplicate-requisition guard via idempotency key on (Material, Plant, RequestedBy, Date).
- Insufficient-authorization or blocked-material errors are surfaced to the requesting agent and logged, not silently retried.

## Sample Payload (Purchase Requisition Create)
```json
{
  "Material": "SP-BRG-6205-2RS",
  "Plant": "PLANT-A",
  "Quantity": 12,
  "RequiredDate": "2026-08-18",
  "Requester": "AI_SPAREPARTS_AGENT",
  "Justification": "Predicted consumption spike based on 90-day failure trend on Line 3 conveyor bearings"
}
```

## Use in This Use Case

The Spare Parts Intelligence Assistant uses SAP MM as its transactional system of record for two things it must never treat as approximate: the material master (criticality class, min/max stock parameters, base unit) and current on-hand stock. Concretely:

- **Material master read:** The Spare Recommendation and Inventory Analyzer skills pull `MM03` fields (Material No., Description, Criticality Class, Base Unit) at the start of every analysis cycle to ground recommendations in the field values published in `Sample Data/spare_part_master.csv` (`material_id`, `description`, `criticality_class`, `min_stock`, `max_stock`, `lead_time_days`).
- **Stock overview read:** `MMBE`-equivalent reads (Plant, Unrestricted Stock, Safety Stock, Reorder Point) feed the Inventory Analyzer skill's current-position calculation, which is compared against the AI-recommended min/max before any alert or recommendation is generated.
- **Purchase requisition write-back:** When the Cost Optimization and Vendor Recommendation skills agree on a procurement action, the plugin drafts a purchase requisition payload (Material, Plant, Quantity, Required Date, Justification) identical in shape to the canonical sample payload above, and submits it via `API_PURCHASEREQ_PROCESS_SRV`. The requisition always carries a natural-language `Justification` string generated by the LLM layer (e.g., citing the forecast model, the criticality class, and the triggering consumption trend) so the human approver in SAP's release workflow has full context without leaving SAP.
- **Guardrail:** the plugin's SAP MM service user (`SVC_AI_SPAREPARTS`) is never granted PO release authority — every AI-originated requisition lands in the buyer's SAP workflow inbox for approval, consistent with the `human_approval_required_for` list in `Plugin/plugin.json`.
